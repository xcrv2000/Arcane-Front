# 技术约定

本文件记录工程任务需要读取的技术约束。当前内容是占位性的协作约定，不代表项目已经确认具体引擎或框架。

## 当前技术状态

- 已确认主要载体为 Godot。
- 未确认 Godot 版本。
- 未确认前端框架。
- 未确认包管理器。
- 未确认构建命令。
- 未确认测试命令。
- `游戏工程/` 当前没有可见实现文件。
- 已确认主要目标用户为手机竖屏用户；工程和 UI 实现应优先考虑竖屏移动端体验。

## 技术栈确认规则

在没有人类设计师确认、也没有既有工程文件证明的情况下，AI 不得擅自写死尚未确认的技术细节。当前只确认主要载体为 Godot，不代表 Godot 版本、目录结构、插件、渲染管线或构建流程已经确认。

当技术栈确认后，应补充：

- 引擎或框架名称与版本。
- 语言与运行时版本。
- 包管理器。
- 安装命令。
- 本地启动命令。
- 构建命令。
- 测试命令。
- 目录结构约定。

## 临时实现原则

- 原型应小、清晰、可检查、易替换。
- 若实现游戏工程内容，应优先围绕 Godot 组织。
- 若只是辅助说明、数据验证或轻量外部工具，仍可在人类同意或任务需要时使用更轻量的脚本/网页原型。
- 卡牌、敌人、Buff、经济、遭遇、成长等规则优先使用结构化数据表达。
- 游戏设计数据应与渲染/UI 代码分离。
- 不引入大型依赖、游戏引擎、构建系统或外部服务，除非人类确认或现有工程已经采用。

## 代码风格占位约定

- 函数应围绕游戏领域意图命名。
- 核心对象应有清晰类型，例如卡牌、令牌、Buff、敌人、关卡、奖励、玩家状态。
- 战斗逻辑、经济规则、存档、随机生成不要依赖隐式全局状态。
- 随机行为应尽量可测试，例如使用种子 RNG 或可注入随机源。
- 平衡数值优先放在数据或配置中，除非它们属于基础公式。
- 对确定性规则、存档兼容、经济计算、战斗边界情况添加测试。
