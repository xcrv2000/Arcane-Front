# 后续版本路线图

最后更新：2026-08-12

状态：V0.2 已完成人工验收；已确认最终需要联机对战；后续路线建议，待人类确认优先级

本文件用于规划 V0.2 之后的开发路径。它不是已定案的长期 Roadmap；其中除“已完成”与“已确认约束”外，后续版本目标都应在进入实现前由人类确认。

## 已完成

### V0.1：基础验证

- 已完成，人工验收没有发现问题。
- 验证内容：本地玩家对脚本 Bot、8 选 6、常驻 6 卡、费用部署、单位推进、基地胜负、基地分段清屏、中央时钟、几何图形单位表现。

### V0.2：任务进化与设计师文档

- 已完成，人工验收没有发现问题。
- 验证内容：设计师文档、8 张初版卡默认任务、一层自动进化、局内任务进度、进化后卡牌行为、底部卡牌栏状态、事件日志和结算统计。

## 路线原则

- 每个版本只验证一组主要风险，避免一次叠太多系统。
- 不急着扩内容；先让现有 8 张卡、任务进化和对局节奏可读、可调、可复盘。
- 设计数据继续保持设计师可读，代码数据继续保持结构清楚。
- 联机是最终产品方向，不应被推到遥远的“以后再说”；但也不建议在 V0.3 直接上完整联机，因为当前更缺的是可读性、调试闭环和可拆分的战斗结构。
- 新功能进入实现前，先确认它是否属于当前版本目标。

## 建议 V0.3：可玩性验证与调试闭环

核心目标：让 V0.2 的任务进化系统更容易观察、调参和复盘。

建议内容：

- 任务/进化 UI 可读性提升。
- 进化触发提示与场上反馈增强，仍可使用几何图形和文字，不要求正式美术。
- Bot 卡组和行为覆盖法术任务，方便自动观察裂魂矢、星陨等任务。
- 增加开发者调试工具，例如快速加费、快速触发任务、固定随机种子、重开对局。
- 结算统计和事件日志更适合设计师复盘。
- 第一轮数值调参流程：用设计师文档记录每次调整原因、预期和结果。
- 记录当前本地原型中会影响未来联机的风险点，例如输入命令、随机数、事件顺序、状态同步和 UI 与战斗逻辑耦合。

建议不做：

- 新卡池扩充。
- 局外任务配置。
- 多层或分支进化。
- 联网对战实现。
- 正式美术和音效。

## 建议 V0.4：联机前工程结构整理

核心目标：把 V0.1/V0.2 快速原型整理成可维护、可调试、可接入联机的工程结构。

建议内容：

- 拆分当前较集中的对局脚本，分离卡牌数据、任务系统、进化系统、战斗事件、输入命令、Bot、UI。
- 建立“玩家意图命令”层，例如出牌、目标点、卡牌索引、时间戳或序号，让本地玩家、Bot 和未来远端玩家都走同一入口。
- 梳理战斗模拟对随机数、帧率、节点顺序和 UI 状态的依赖，记录哪些部分需要确定性或服务端权威。
- 建立事件日志或回放雏形，用于复盘任务完成、单位生成、基地受击和胜负判定。
- 约定卡牌数据与设计师文档的同步流程。
- 评估是否将卡牌数据迁移到更适合设计师编辑的格式，例如 Godot Resource、JSON 或继续 GDScript 字典。
- 建立更稳定的自动化检查入口，减少依赖本机临时 Godot 路径。
- 增加数据完整性检查，例如每张卡必须有费用、说明、任务、进化和设计师文档条目。

建议不做：

- 大量新玩法。
- 正式导出发布。
- 大规模 UI 重做。
- 完整联网、匹配、账号或排行榜。

## 建议 V0.5：最小联机对局原型

核心目标：证明游戏可以从本地原型进入真实双端对战，不先扩内容。

建议内容：

- 搭建最小房间流程：创建房间、加入房间、双方准备、开始对局。
- 双方仍使用当前 8 张卡和 6 卡配置，不在本版本扩大内容变量。
- 让本地玩家和远端玩家都通过 V0.4 的输入命令层出牌。
- 实现基础状态同步或权威状态下发，至少覆盖费用、出牌、单位生成、基地血量、任务进度、进化状态和胜负。
- 加入基础网络诊断显示，例如连接状态、延迟、重连/断线提示和同步错误提示。
- 保留脚本 Bot 作为离线验证入口，但明确它不是联机对战的替代。

进入前需确认：

- 采用服务端权威、房主权威还是确定性同步。
- V0.5 首个目标是同机双客户端、局域网，还是经远端服务器的互联网对战。
- 是否允许先使用临时房间码，不做账号、匹配和好友系统。
- 若采用服务器，需要确认服务器运行位置、部署方式和维护边界。

## 建议 V0.6：移动端联机体验与构建验证

核心目标：让竖屏手机上的联机体验真正可测。

建议内容：

- Android 或目标移动平台导出验证。
- 触控部署手感、卡牌按钮尺寸、任务/进化信息密度检查。
- 不同屏幕比例和分辨率适配。
- 移动网络、后台切换、断线重连和弱网提示初步验证。
- 性能和电量初步观察。
- 明确项目级 Godot CLI、导出模板、构建命令和验收清单。

进入前需确认：

- 优先 Android、iOS，还是只做桌面竖屏模拟。
- 是否需要安装和记录标准化 Godot CLI 路径。

## 更后续方向

- 更聪明的 Bot 与难度层级。
- 局外配置与卡牌扩展。
- 更正式的视觉、音效和动效。
- 长期养成、卡牌解锁、任务树深度。
- 叙事、世界观和角色表达。

这些方向都不建议在 V0.3 立刻展开，除非人类确认当前项目目标从“系统验证与联机前准备”切换到“内容/产品化验证”。

## 当前需要人类确认

- 是否确认 V0.3 采用“可玩性验证与调试闭环”作为下一版本目标？
- V0.3 是否允许加入开发者调试工具，例如快速触发任务和固定随机种子？
- V0.3 是否要调整 Bot，使其覆盖法术任务和更多进化路线？
- V0.3 的 UI 目标是“原型可读性增强”，还是开始接近正式产品 UI？
- 是否确认联网节奏为：V0.3 记录风险，V0.4 做联机前工程整理，V0.5 做最小联机对局原型？
- V0.5 的首个联机目标应是同机双客户端、局域网，还是互联网服务器？
- 联机架构倾向服务端权威、房主权威，还是确定性同步？
