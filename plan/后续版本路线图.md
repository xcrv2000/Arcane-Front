# 后续版本路线图

最后更新：2026-08-13

状态：V0.1/V0.2 已完成人工验收；V0.3 已完成实现待验收；V0.4 已实现联机对局（确定性锁步 + 定点数 + Python asyncio TCP 中继 + 房间码 + 互联网经云服务器）；V0.45 已确认并完成主体实现：ENet 联机传输层改造（服务器重写、去 NO_OP、优先网络性能）；V0.5 释放为联机增强；原 V0.4「工程结构整理」已提前完成

本文件用于规划 V0.2 之后的开发路径。它不是已定案的长期 Roadmap；其中除“已完成”与“已确认约束”外，后续版本目标都应在进入实现前由人类确认。

## 路线原则

- 每个版本只验证一组主要风险，避免一次叠太多系统。
- 不急着扩内容；先让现有 8 张卡、任务进化和对局节奏可读、可调、可复盘。
- 设计数据继续保持设计师可读，代码数据继续保持结构清楚。
- 联机是最终产品方向，不应被推到遥远的“以后再说”；V0.4 直接实装联机对局。
- 新功能进入实现前，先确认它是否属于当前版本目标。

## V0.4：联机对局（已实现基线，详见 `plan/V0.4联机对局开发计划.md`）

核心目标：证明游戏可以从本地原型进入真实双端互联网对战，并建立确定性锁步联机工程基础。

已确认架构与边界：

- 确定性锁步：双端各跑完整模拟，只同步玩家输入命令；服务器不跑战斗逻辑。
- 定点数整数运算保证确定性（重写 `map_math`/`battle_simulator` 几何与数值，消除浮点/sqrt 分歧）。
- Python asyncio 标准库 TCP 中继服务器：中继 + 房间码 + 仅持久化对局结果，不承担战斗计算。
- 互联网经公网云服务器中转验证；房间码建房/加入，无账号。
- 断线采用暂停等待 + 超时判负，不做完整重连。

开发阶段（P0–P5）：

- P0：输入命令层 + 固定 tick 模拟基础（不联机，先确定性自一致）。
- P1：定点数化 — 几何与数值确定性。
- P2：锁步调度 + desync 校验和，本机双实例跑通整局。
- P3：Python asyncio 中继服务器 + 房间码流程。
- P4：互联网端到端打通 + 断线暂停/超时判负 + 网络诊断 UI。
- P5：收尾 — 保留 Bot、同步协作文档、修复遗留 git 冲突标记。

V0.4 不做：

- 账号、正式匹配、好友、排行榜或商业化。
- 完整断线重连/状态重同步。
- 移动端导出与竖屏真机联机验证（V0.6）。
- 新卡、新玩法、多层进化、局外配置。
- 正式美术与音效。
- 服务端权威架构（已按服务器算力约束排除）。

## 当前 V0.45：ENet 联机传输层改造（详见 `plan/V0.45ENet联机改造计划.md`）

核心目标：把联机传输从 TCP + JSON Lines 切换为 ENet over UDP，并取消线上逐 tick NO_OP，降低弱网下的卡顿/desync 频率。

已确认架构与边界：

- 底层传输：ENet over UDP；服务器重写，优先网络性能，仍不做服务端权威。
- 服务器首选 Go + codecat/go-enet；备选 Rust + rusty_enet。
- 客户端使用 Godot `ENetMultiplayerPeer` raw packet 承载自定义协议。
- 线上只传真实 PLAY_CARD 与 CHECKSUM；缺省即 NO_OP，迟到真实命令走本地回滚。
- 保留 V0.4 的锁步、定点数、房间码、断线重连、检查点重同步、desync 自动恢复。

开发阶段（P0–P5）：

- P0：Godot ENet ↔ 新服务器协议互通冒烟。
- P1：Go ENet 中继服务器重写。
- P2：Godot 客户端网络层切换。
- P3：锁步去 NO_OP + 回滚适配。
- P4：断线重连与 desync 重同步验证。
- P5：性能矩阵与验收。

## 建议 V0.5：联机增强与移动端前置

核心目标：在 V0.4 联机对局基础上增强网络健壮性，并为移动端联机体验铺路。原 V0.5「最小联机对局原型」目标已前移至 V0.4 完成。

建议内容：

- 完整断线重连与状态重同步（V0.4 只做暂停+超时判负）。
- 网络抖动与弱网优化、延迟补偿、卡顿缓解。
- 房间/匹配流程增强（如快速 rematch、断线后回到房间）。
- desync 监控与对局复盘/回放雏形。
- 锁步参数（tick 率、输入延迟）按真实手感反馈调优。
- 评估是否进入 V0.6 移动端导出与竖屏真机联机验证。

进入前需确认：

- V0.4 定点数手感与 desync 稳定性是否达标。
- 是否优先补齐断线重连，还是先推进移动端。

## 建议 V0.6：移动端联机体验与构建验证

核心目标：让竖屏手机上的联机体验真正可测。

建议内容：

- Android 或目标移动平台导出验证。
- 触控部署手感、卡牌按钮尺寸、任务/进化信息密度检查。
- 不同屏幕比例和分辨率适配。
- 移动网络、后台切换、断线重连和弱网提示初步验证。
- 性能和电量初步观察。
- 明确项目级 Godot CLI、导出模板、构建命令和验收清单。

进入前需确认：

- 优先 Android、iOS，还是只做桌面竖屏模拟。
- 是否需要安装和记录标准化 Godot CLI 路径。

## 更后续方向

- 更聪明的 Bot 与难度层级。
- 局外配置与卡牌扩展。
- 更正式的视觉、音效和动效。
- 长期养成、卡牌解锁、任务树深度。
- 叙事、世界观和角色表达。

这些方向都不建议在 V0.4 立刻展开，除非人类确认当前项目目标从“联机验证与工程基础”切换到“内容/产品化验证”。

## 当前需要人类确认

- 定点数精度（Q*1000）与移动量化手感是否可接受；若不可接受是否提高精度或回退。
- 锁步默认参数（tick 20Hz、输入延迟 2 tick、desync 校验间隔 10 tick）是否合适。
- desync 发生时是暂停提示重开还是自动判和。
- 联机中继服务器部署细节（端口、防火墙、是否需要域名/HTTPS）。
- 若设计师在 V0.3 试做新卡，需要确认新卡数量、定位、任务和进化规则。
