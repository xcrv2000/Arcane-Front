# V0.3 可玩性验证与调试闭环开发计划

最后更新：2026-08-12

状态：已确认为当前下一版本计划，待实现

## 版本目标

V0.3 的目标是把 V0.2 已完成的任务进化系统变得更可玩、可读、可调。

需要验证的问题：

- 玩家是否能在竖屏中清楚理解每张卡的任务进度和进化状态。
- 进化触发是否足够明显，设计师能否知道为什么触发。
- Bot 是否能帮助观察多数卡牌任务，而不是只验证单位牌。
- 设计师是否能通过结算、日志和文档完成一轮数值调参。
- 当前费用 0.5/秒、8 张卡任务条件和进化效果是否形成合理节奏。
- 当前本地原型有哪些地方会阻碍后续联机，例如输入、随机数、事件顺序、状态同步和 UI/战斗逻辑耦合。

## 已确认基础

- V0.1 已完成，人工验收没有发现问题。
- V0.2 已完成，人工验收没有发现问题。
- 当前仍使用 Godot 4.5 stable 与 GDScript。
- 已确认最终产品方向需要联机对战；当前对局仍是本地玩家对脚本 Bot，V0.3 不做联网实现。
- 当前单位仍可使用几何图形加文字，不要求正式美术。
- V0.3 不要求做新卡；但设计师如果希望新增或试做少量新卡，可以在明确卡牌目标后作为可选工作加入。
- V0.3 开发者调试工具是允许且有价值的，但不应占据主要视觉，只在对局明确需要时开启。
- V0.3 Bot 可以改成从当前可用卡池中随机选择 6 张。
- 已确认联机节奏：V0.3 只做联机前风险记录，V0.4 再做工程拆分，V0.5 再做最小联机对局原型。
- V0.3 不应擅自扩展新卡、多层进化、局外任务配置或跨局任务进度。

## 推荐开发阶段

### P0：V0.2 收尾与 V0.3 入口

目标：记录 V0.2 已完成，并把 V0.3 作为当前下一版本入口。

交付：

- 已更新 V0.2 计划状态为已完成。
- 已更新当前状态页，记录 V0.2 人工验收通过。
- 已根据人类确认，将 `AGENTS.md` 当前版本计划入口切换到 V0.3。

验收：

- 后续协作者不会误以为 V0.2 仍等待验收。
- 后续协作者能明确知道 V0.3 已是当前下一版本计划。

### P1：任务与进化 UI 可读性

目标：让设计师和玩家能更快理解任务进度、完成原因和进化状态。

建议交付：

- 卡牌栏任务进度显示优化。
- 进化完成提示，例如短暂文字、颜色变化、事件日志置顶或卡牌状态高亮。
- 卡牌详情或长按/点击信息区，展示任务条件和进化效果。
- 结算中列出每张卡是否完成任务、何时进化、使用次数。

验收：

- 不读代码也能看懂每张卡任务是否接近完成。
- 进化触发后，玩家能在 1 秒内看出是哪张卡进化。

### P2：Bot 覆盖与验证脚本

目标：让自动对局更容易覆盖任务进化系统。

建议交付：

- Bot 开局从当前可用卡池中随机选择 6 张，方便观察更多任务组合；若随机结果不包含法术，可通过固定随机种子或调试入口复现/调整。
- Bot 行为能选择合适目标施法，而不是只出单位。
- 可选开发者开关：指定 Bot 卡组、固定随机种子、加速出牌。
- 保持 Bot 仍然是简单脚本，不做复杂 AI。

验收：

- 不依赖纯手动操作，也能观察更多任务类型。
- Bot 修改不会破坏 V0.1/V0.2 基础闭环。

### P3：开发者调试工具

目标：减少设计师验证任务和进化的时间成本。

建议交付：

- 快速加费或设置费用。
- 快速触发选中卡任务。
- 重开对局并保留当前卡组选择。
- 显示当前随机种子或允许固定随机种子。
- 调试工具只在原型/开发模式中出现，默认收起或隐藏。
- 调试工具不占据主要视觉区域；只有在对局明确需要调试时，才通过按钮、快捷键或开发开关展开。

验收：

- 设计师能在短时间内检查 8 张卡的进化效果。
- 调试工具不会被误认为正式玩家功能。
- 关闭调试工具时，主对局视觉不被调试面板挤占。

### P4：调参与设计师文档闭环

目标：让卡牌调整有记录、有原因、有结果。

建议交付：

- 在设计师文档中增加“调参记录”小节。
- 每次调整记录：调整项、原因、预期结果、验收反馈。
- 明确文档变化后是否需要同步代码的询问流程。
- 可选：增加简单数据一致性检查清单。

验收：

- 设计师能追踪为什么某张卡被改过。
- 开发人员不会静默忽略设计师文档变化。

### P5：联机前风险记录

目标：不在 V0.3 实现联网，但把下一阶段需要拆的技术风险列清楚。

建议交付：

- 记录当前对局脚本中本地输入、Bot 输入、战斗模拟、UI 展示和结算统计的耦合点。
- 记录出牌命令需要包含的信息，例如玩家、卡牌、目标点、时间或序号。
- 记录任务/进化、随机数、单位生成顺序、基地清屏和胜负判定对同步的要求。
- 给 V0.4 拆分任务提供清单，避免 V0.4 重新摸索。

验收：

- 后续协作者能根据清单判断哪些代码必须先拆，哪些可以等最小联机原型时再处理。
- V0.4 的工程整理不只是“变整洁”，而是明确服务于 V0.5 最小联机。

### P6：V0.3 可玩验收

目标：证明 V0.3 没有新增大型系统，但显著改善可读性和调参效率。

建议验收清单：

- 完成 3 局普通对局，确认 V0.1/V0.2 闭环稳定。
- 手动或调试触发 8 张卡进化，确认 UI 与结算可读。
- 让 Bot 至少触发或接近触发部分任务。
- 记录一轮数值调整建议，并同步到设计师文档。

## V0.3 不做

- 强制新卡扩充；若设计师明确想在 V0.3 试做新卡，可作为可选内容处理。
- 局外任务配置。
- 多层或分支进化。
- 跨局任务进度。
- 联网对战实现。
- 正式美术、正式音效、正式发布导出。
